# X/Y/Z/M 陪伴型记忆纠偏方案

## 1. 目标

让 X/Y/Z/M 服务于陪伴型 AI 的长期记忆：完整记录小雨的重要事情、AI 自己的变化、共同经历与关系脉络。

代码和提示词必须简洁。每条规则只表达一个含义，删除解释性复述、同义堆叠和无业务作用的文案。

## 2. 统一记忆范围

长期记忆包含三类主体：

1. 小雨：偏好、经历、计划、状态变化、边界和重要人物。
2. AI：感受、思考、自我认识、长期倾向和自身边界。
3. 双方：共同经历、约定、称呼、关系变化和长期话题。

三类主体地位相同。小雨的重要事项可以直接进入长期记忆和时间线。

## 3. X：时间线

### 修改目标

时间线串联持续发展的经历或事项，覆盖小雨、AI 和双方。

### 提示词

将当前偏向旅行、求职、考试、项目的定义替换为：

```text
时间线用于串联持续发展的重要经历或事项，包括小雨的生活变化、我的变化、共同经历、长期约定与关系发展。
```

JSON 示例保持中性：

```json
{
  "title": "时间线标题",
  "summary": "这段经历目前的发展脉络",
  "card_ids": ["相关卡片ID"]
}
```

### 保留

- 从直接命中卡片触发 X 扩展。
- 最多补充两张卡片。
- 优先选择较新的有效进展。
- 所有权、状态、去重和 Token 预算规则。

## 4. Y：记忆关系

### 修改目标

Y 恢复完整脉络，连接以下内容：

- 小雨不同事情之间的关联；
- AI 不同记忆之间的关联；
- 小雨的经历与 AI 感受、理解或回应之间的关联；
- 双方共同经历之间的关联。

### 提示词

```text
关系边用于连接有明确联系的记忆，帮助我恢复事情、人物和相处脉络。关联可以存在于小雨的经历之间、我的记忆之间，以及双方记忆之间。
```

### 第一阶段关系类型

继续使用现有类型：

- `same_event`
- `same_topic`
- `temporal_sequence`
- `derived_from`
- `same_person`
- `supports`
- `contradicts`
- `cause_effect`

第一阶段不新增关系类型。现有类型不足的真实样本累计后再评估扩展。

### 保留

- 一跳扩展。
- 证据来源和关系强度校验。
- 高风险关系进入 REVIEW。
- 状态、所有权、去重和数量限制。

## 5. Z：事实演化

### 修改目标

Z 继续识别同一事项随时间发生的变化。适用对象包括小雨、AI 和双方关系。

### `fact_key` 示例

```text
person.preference.food_spicy
person.life.work_status
self.preference.communication
relationship.naming
relationship.promise.continuity
```

`fact_key` 由模型生成，用于识别同一演化事项，不展示为要求小雨填写的概念。

### 保留

- 同一 `fact_key` 的唯一有效状态检查。
- 冲突进入审核。
- 旧卡保留演化记录。
- SUPERSEDE 需要明确规则或人工确认。

## 6. M：记忆维护

### 修改目标

降低低频但重要的陪伴记忆被建议归档的概率。

### 冷记忆保护

满足任一条件时，不生成 `COLD_INACTIVE` 建议：

- `isProtected=true`；
- 类别为 `self`、`relationship` 或 `boundary`；
- 属于 ACTIVE 时间线；
- `importance` 高于现有冷记忆阈值。

`experience` 和 `plan` 不按类别整体保护，由重要度、时间线成员关系和人工保护共同决定。

### 保留

- M 只生成维护建议。
- 修订频繁、归档后重新触及、待审积压和时间线容量巡检。
- 人工处理入口和任务抑制机制。
- 不自动归档、改写或删除卡片。

## 7. 稳定自我边界

`self` 的定义、证据 episode、成熟条件、冲突闸门、常驻注入和试行数据处理，完全遵循：

`local-memory-stable-self-companion-correction-plan.md`

本方案只保证 X/Y/Z/M 能正确组织和维护 `self` 卡，不重复实现稳定自我规则。

## 8. 修改文件边界

### 允许修改

- `MemoryConsolidationService.kt`
  - X/Y/Z 生成提示词与 JSON 示例。
- `MemoryMetabolismInspector.kt`
  - M 冷记忆保护条件。
- 对应 JVM 测试。

仅在现有测试无法覆盖时，允许增加一个小型纯函数。函数只负责判断卡片是否获得冷记忆保护。

### 禁止修改

- Room schema、数据库版本和迁移。
- X/Y/Z/M 的表结构。
- 召回排序、RRF、Token 预算和数量上限。
- X 的种子触发机制。
- Y 的一跳限制和关系审核机制。
- Z 的人工确认与演化历史。
- 稳定自我方案正在处理的文件和逻辑。
- UI 页面、导航、主题和无关模块。
- 既有卡片正文、状态和时间线成员。

## 9. 提示词写作约束

写入橘瓣的新增或改写提示词必须满足：

- 使用短句。
- 一个含义只出现一次。
- 直接说明期望输出。
- 示例只用于说明格式或覆盖范围。
- 不加入角色宣言、背景故事或解释性总结。
- 不使用“不是……而是……”句式。
- 不重复系统提示、工具描述或 JSON 字段已经表达的规则。

完成修改后逐段检查；删除任一重复句不会损失约束含义时，应删除该句。

## 10. 测试

### X/Y/Z 提示词

1. 时间线定义覆盖小雨、AI 和双方。
2. 时间线提示词不再使用工作型事项列表作为主要定义。
3. 关系提示词保留小雨不同事情之间的关联。
4. `fact_key` 示例覆盖三类主体。
5. 提示词不包含重复规则和禁用句式。

2. ACTIVE 时间线成员不产生冷记忆归档建议。

4. 普通低重要度冷卡仍产生建议。
5. 高频修订、归档回潮、待审积压和时间线巡检不回归。

