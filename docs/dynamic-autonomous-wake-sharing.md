# 动态自主唤醒与事项分享实现决策

日期：2026-09-26
范围：助手自主唤醒的时间计算、持久事项、幂等投递、调度恢复与后台页面。用户聊天、工作流、插件触发保持原入口。

## 时间与事项

- 用户间隔是自主唤醒的默认等待时间；自主输出中的 `next_wake_delay_minutes` 在 15 分钟至 24 小时内生效，缺失或无效时回退默认值。截取后的实际值、原因和原建议持久化并反馈到下轮上下文。
- 每个助手只保留一个自主候选时间。计划执行结束时以结束时间为基准重新计算。
- 活动事项可有带时区 `resume_at`。最终计划取自主候选时间与最早有效事项时间的较早值；事项触发后，若仍逾期且未被完成、取消或改期，自动安排 15 分钟复查，避免过去时间导致的唤醒循环。
- 计划持久化候选时间、采用时间、来源、理由和单调递增版本。AlarmManager 与 WorkManager 携带相同版本；数据库条件领取保证一个版本只执行一次。新版本不能被旧运行结束逻辑覆盖。
- 用户关闭开关会取消排程并保留事项；开启或修改默认间隔时按现存事项重新计算。系统实际执行时间由 Android 调度策略决定，页面仅承诺目标时间。

## 事项与投递

- 每个助手的持久事项以稳定 ID 标识，记录内容、进展、状态及可选到期时间。旧 `currentItem` 仅迁移为一个活动事项，旧运行记录继续作为历史。
- 自主专用工具负责事项创建、更新、完成、取消和结果分享；工作流/插件原工具面不改变。
- 具体事项分享要求事项 ID 与结果 ID；数据库唯一键为助手、事项、结果。同键重试返回第一次保存的正文、时间及消息 ID，即使本次正文不同也不重复写入。普通表达使用持久请求 ID 幂等。
- 联系冷却与近期用户活动条件在同一助手串行锁内检查。暂缓结果携带原因与最早重试时间；重试仍重新检查条件。旧 `should_contact/message` 兼容并经相同投递逻辑，同轮已调用分享工具时不再额外投递。
- 聊天消息与投递回执由 ConversationRepository 在同一 Room 事务中持久化；事务成功后才更新 ChatService 内存状态并发送通知。通知失败不撤销回执。
- 外部副作用只重放已确认幂等的调用；执行结果不确定的非幂等调用标记为不确定并在下一轮告知 AI。

## 持久化与验证

- 新增 Room 迁移和表：助手事项、计划状态、分享回执；对事项/结果幂等键建立唯一索引。保留现有运行记录和工具记录。
- 页面显示自主候选、事项候选、最终计划、采用理由、事项状态、分享反馈及结果不确定工具步骤。
- 先验证纯 Kotlin 时间选择/JSON兼容/幂等规则，再跑相关 JVM 测试与 `:app:compileDebugKotlin`。系统闹钟、Doze、进程恢复和通知仅可由真机验收，JVM与编译不能替代。
